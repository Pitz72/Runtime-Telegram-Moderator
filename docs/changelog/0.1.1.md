# Changelog - v0.1.1

## [0.1.1] - 2026-09-28

### 🛡️ Risoluzione Criticità & Security Hardening

Questa versione risolve integralmente tutte le criticità gravissime, gravi e medie individuate nell'audit architetturale e di sicurezza.

- **Sicurezza dei Token Bot (Privacy-First)**:
    - Implementata utility crittografica `backend/src/utils/crypto.ts` con cifratura simmetrica **AES-256-GCM** a riposo nel database SQLite.
    - Introdotta la funzione `maskToken()`: le API REST (`GET /api/bots`, `GET /api/bots/:id`, `POST /api/bots`) non espongono mai più i token in chiaro, restituendo esclusivamente `tokenMasked` (es. `123456789:•••••••••••abcd`).
    - Validazione sintattica rigorosa dei token BotFather tramite regex (`isValidTelegramToken`).
- **Sanificazione Repository Git**:
    - Rimosso `backend/dev.db` dall'indice di tracciamento di Git (`git rm --cached`).
    - Aggiornato `backend/.gitignore` e creato il `.gitignore` di root per escludere tutti i file di database SQLite (`*.db`, `*.sqlite`, `*.db-wal`, `*.db-shm`).
- **Resilienza Multi-Bot Engine (`BotManager`)**:
    - Integrata la libreria `@grammyjs/runner` per l'orchestrazione sicura e concorrente di bot multipli nello stesso processo Node.js.
    - Aggiunta la validazione preventiva tramite `await bot.api.getMe()`: se il token è errato o revocato (HTTP 401), l'errore viene catturato senza scatenare unhandled promise rejections, prevenendo il crash del processo.
    - Sincronizzazione atomica e bidirezionale dello stato: `stopBot` aggiorna sempre `isRunning: false` nel DB anche se il bot non è presente in memoria; `startBot` salva lo `@username` reale del bot.
- **Ottimizzazione SQLite & Concorrenza**:
    - Abilitata la modalità **WAL** (`PRAGMA journal_mode = WAL;`) e `PRAGMA busy_timeout = 5000;` tramite il modulo `backend/src/db/prisma.ts`.
    - Eliminati i colli di bottiglia e i blocchi `SQLITE_BUSY` sotto carico concorrente.
- **Aggiornamento Schema Prisma & Cascade Delete**:
    - Aggiunto `onDelete: Cascade` sia a `GroupConfig` che a `Log` per consentire l'eliminazione pulita dei bot senza errori di foreign key.
    - Aggiunti indici prestazionali su `Log` (`botId`, `timestamp`, `level`) e su `GroupConfig` (`botId`).
    - Aggiunto campo `username` al modello `Bot`.
    - Applicata migrazione `20260928212352_cascade_and_indexes`.
- **Completamento API REST Express 5**:
    - Implementati gli endpoint `DELETE /api/bots/:id` (arresto bot e cascade delete) e `GET /api/bots/:id`.
    - Implementato `GET /api/logs` con paginazione (`limit`, `offset`) e filtri per `botId` e `level`.
    - Implementati `GET /api/bots/:id/groups` e `POST /api/bots/:id/groups` (upsert).
    - Gestione del Graceful Shutdown (`SIGINT`, `SIGTERM`) con `botManager.stopAll()`.
- **Riallineamento Tooling & Test Suite**:
    - Risolto disallineamento `package-lock.json` e ripristinato l'ambiente locale nativo con `vitest 2.1.9` e `Node 22`.
    - Aggiornata la suite di test (unit e integration) con 26 test su 26 passati con successo (`100% pass`).
    - Build `tsc` pulita e senza errori.
    - Dockerfile ottimizzato per produzione con volume data preconfigurato.
    - Linee guida `CLAUDE.md` aggiornate per supportare sia Docker che lo sviluppo locale.
